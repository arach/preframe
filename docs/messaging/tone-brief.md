# Tone & constraints (operator brief)

This is **not** a design brief. Visual scaffolding is done. Rethink **words, taxonomy, and information architecture** only.

## Voice target

- Personal, low-key, first-person where it fits
- Like showing someone your setup: "here's what I use, hope it's useful"
- **Not** a product launch, manifesto, or magic-elixir pitch
- **Not** job-permission / compliance / enterprise policy writer voice
- **Not** clever tagline twists ("X until it isn't", "the whole point", "before the cut")
- Plain sentences. Short beats. No architecture-diagram copy in user-facing text.

## Known problems with current copy

- Still drifts into spec-writer / permission-writer cadence in places
- Repeated thesis statements about source↔video sync feel preachy
- Some pages (especially `/concepts/`) are much more grandiose than `/`
- Cross-page taxonomy is inconsistent (loop names, rail labels, mode names)
- README tagline (`stage the prompt, review the cut, ship the frame`) may not match site tone

## What stays fixed (do not redesign)

- Dark editorial UI, Hudson window chrome, player-first layout
- Walkthrough / story mode mechanic (stills + narration beats)
- Playlist + watch/review/effects tabs
- Existing media assets and demo clips
- `bun run dev:site` for local preview

## Deliverable expectation

Propose better **site taxonomy** and **messaging map**, with sample copy per zone. Implementation comes later — do not edit HTML in this mission.
